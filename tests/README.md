# Headless-тесты UI

Гоняются без устройства и без сборки APK: `python3 -m http.server 8099` в `web/` +
`chromium --headless --no-sandbox --disable-gpu --remote-debugging-port=9223
--user-data-dir=/tmp/cr-detail`, затем `BASE=http://127.0.0.1:8099 node <тест>.mjs`.
Негативный контроль — тот же тест с `BASE=http://127.0.0.1:8098` на старом `app.js`
(HEAD); если надо проверить предложенный кем-то патч — копия `web/` с этим патчем на
своём порту (так сделан `searchrace.mjs`: 8099 = текущий код, 8097 = вариант с `return`).

| Тест | Что проверяет |
|---|---|
| `ptrsync.mjs` | pull-to-refresh запрещается, пока прокручен оверлей карточки (`.dbody`), и возвращается в начале/при закрытии |
| `cardupdremove.mjs` | установка из карточки убирает строку из списка обновлений (и тост «обновлён», а не «Установлено») |
| `popularhdr.mjs` | рейл «Популярное сейчас» рисуется: запрос к `popular/apps` уходит С заголовком `RuStoreVerCode` (без него API отвечает 400) |
| `dlfallback.mjs` | `v3/download-link` ответил 200 без `downloadUrls` → идём в старый backapi-путь, а не падаем «RuStore не отдал ссылку» |
| `afterinstall.mjs` | после установки: кнопка в карточке меняется на «Открыть» (реактивность через `ST.rowBusy`) и приложение появляется во вкладке «Установленные» (`refreshInstalled`) |
| `chiprows.mjs` | карточка A (4 чипа/4 строки/2 скриншота) → карточка B (1 чип/3 строки) → снова A: `CHIP`/`ROW` без `window.ID` не смешивают инстансы и не оставляют чужих значений |
| `ptrcard.mjs` | PTR не рассинхронизируется: прокрученное тело карточки остаётся прокрученным после перерисовки внутри неё (загрузка отзывов), инвариант «PTR выключен ⟺ `.dbody.scrollTop > 0`» держится, при закрытии/переоткрытии сбрасывается |
| `iconslazy.mjs` | иконки «Установленных» грузятся лениво и порциями (60 приложений): на старте 0 вызовов моста, в первом рендере 4 (не 60), список сразу с буквами-заглушками, через 3 с все 60; после обновления одного пакета — 61-й вызов и `__cacheStats().icons === 60` (старая версия выброшена) |
| `searchrace.mjs` | «гонка при очистке поиска»: `history.back()` из пустой ветки не вызывается вообще (инструментированный `history.back` → 0 вызовов: инпут есть только на apps/games, а они всегда в `navStack`); при злом тайминге (очистка + клик по плитке в одном таске) карточка устояла, один back закрывает именно карточку и вкладка остаётся; вариант с предложенным `return` ведёт себя так же, но теряет `clearTimeout(qT)` → лишний запрос подсказок (1 против 0) |
| `rowinstall.mjs` | объединённый `runInstall` со стороны строки списка: обычное обновление (строка уходит, тост «обновлён», `refreshInstalled` перечитал «Установленные», в натив ушло имя `pkg-2.apk`), замороженное приложение (`UNFREEZE` → установка → `FREEZE`), откат на системный установщик (`installed:false`) — «Обновить все» останавливается после первой такой строки и ничего не убирает |
| `installstall.mjs` | сторож установки: натив замолчал после одного тика прогресса → ошибка «система не отвечает» и **снятие блокировки** (кнопка снова «Обновить», следующая установка проходит); живой прогресс → сторож молчит, установка доходит до конца; фаза `permission` + тишина → сторож снят, строка остаётся «Разрешите установку». Негативный контроль (старый `native.js`) — кнопка навсегда «50%», и все следующие установки заблокированы |
| `railmeta.mjs` | рельсы на `ST.meta` (вместо словаря `refs`): пакет из кэша рисуется сразу и повторно не запрашивается, свежий — сначала буквой-заглушкой и потом точечно; один и тот же пакет в двух рельсах получает мету в обеих плитках; пакета нет в RuStore — плитка остаётся заглушкой |

Исторические тесты (жили в `/tmp`, потеряны при перезагрузке — воссоздавать по мере
надобности): `updlist` (список обновлений: 404/сеть/удаление), `updrace` (гонки
проверки), `installphase` (промис резолвится по `installed`, а не по открытию
установщика), `rowbusy` (занятость строки живёт в состоянии и переживает
перерисовку), `cardhail` (карточка размораживает и морозит обратно), `detailrace`,
`backsentinel`, `selfupd`, `visjump2`.

Важно: `const`/`let` из `app.js` не видны через CDP (indirect eval) — проверять
через DOM. Стаб ставится через `Page.addScriptToEvaluateOnNewDocument`.

Важно-3: `window.Native.installApk` передаёт в натив **JSON-строку**
(`BT.installApk(JSON.stringify({...}))`), а не объект. Стаб `WebToApk.installApk`
обязан делать `JSON.parse`, иначе не найдёт `name`/`url` и «установка» молча
не применится (тест покажет «Установка не применилась»).

Важно-4: стаб — это JS-строка внутри template literal, поэтому `\/` в регулярке
схлопывается в `/`, регулярка разваливается («Invalid regular expression flags»),
стаб молча не выполняется — и тест уходит в **реальный API**, «проходя» на настоящих
данных. Писать `\\/` и держать страховку сразу после `Page.navigate`:
`if ((await ev('typeof window.__myStubFlag')) !== 'object') { ...exit(1) }`
(сделано в `railmeta.mjs`).

Важно-2: `Page.addScriptToEvaluateOnNewDocument` живёт до конца жизни процесса
браузера, а не таба. Стабы разных тестов протекают друг в друга — после теста со
стабом надо перезапускать chromium (иначе видно синтетические данные: имена вида
`APP-<pkg>` из стаба `cardupdremove.mjs`).
